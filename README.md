# IME Indicator

> 屏幕底部的中英文输入状态提示条。切换输入法时弹一下，让你**一眼看出现在打出来的是中文还是英文**，不用低头找任务栏角落那个小图标。

```
┌────────────────────────────┐
│ ┃  中   中文输入             │      蓝   = 中文
│ ┃       半角                 │      琥珀 = 中文输入法内切到了英文
└────────────────────────────┘      绿   = 英语键盘
```

纯 Python 标准库（tkinter + ctypes + winreg），**无第三方依赖、单文件、绿色免安装、不联网**。

---

## 特性

- **读真实状态，不猜快捷键**。直接读前台焦点控件的输入法状态，鼠标点语言栏、点托盘输入法图标、按 `Shift`、按 `Alt+Shift`、在系统设置里改，全都能反映出来。
- **三种状态分得清**。中文输入法按 `Shift` 切到的英文，和整个语言切到"英语键盘"的英文，本来长得一模一样；这里用**颜色 + 文案**区分开。
- **切换窗口也能提示**（可选）。Windows 是「每个窗口各自记住输入法」的，切过去先看一眼很实用。
- **响应快**。60ms 轮询 + 键盘钩子加速，实测从按下到弹出通常 < 100ms。
- **不干扰全屏游戏**。默认在全屏应用里静默，不弹窗、不掉帧。
- **托盘常驻**。右键可切常驻显示、透明背景、开机自启、日志，也能打开图形化设置窗口。

---

## 它识别什么

| 项 | 是否识别 | 说明 |
|---|---|---|
| 中文 / 英文 | ✅ 始终准确 | 直接读前台焦点控件的输入法状态 |
| 输入语言（中文键盘 / 英语键盘） | ✅ 始终准确 | 读前台窗口线程的键盘布局（HKL） |
| 全角 / 半角 | ✅ 多数输入法准确 | 少数输入法不写这个状态位，靠 `Shift+Space` 兜底推断；**英语键盘下不检测** |
| 大写锁定 | ✅ | 默认不提示，可在设置里打开 |
| 是哪个输入法 | ❌ 不识别 | 见下文「为什么不显示输入法的名字」 |

### 三种状态能一眼分开

中文输入法按 `Shift` 切到英文之后，和真正切到「英语键盘」看起来完全一样——都是打英文。但从系统角度看，这是两件不同的事：

| 显示 | 颜色 | 含义 | HKL | IMM |
|---|---|---|---|---|
| `中  中文输入` | 蓝 | 打得出中文 | `0804` | native |
| `EN  英文 · 输入法内` | 琥珀 | 同一个中文输入法，按 Shift 关了 | `0804` | 非 native |
| `EN  英文 · 英语键盘` | 绿 | 整个语言切到英语键盘了（Alt+Shift） | `0409` | — |

前两行的键盘布局**完全相同**，只看 IMM 是分不出来的，必须同时读 HKL 的 `langid`。`--once` 也会打印当前语言，方便核对。

全角时下面那行会变成橙色的 `● 全角`。**英语键盘下没有全角这个概念**，那行固定显示 `无全角`，按下 `Shift+Space` 也不会被当成切换全角——否则会弹出一个实际并不存在的变化。

### 为什么不显示输入法的名字

同一种语言（`zh-CN`）下装了多个中文输入法时，**Windows 不向外部程序暴露"当前是哪一个"**：

- 键盘布局 HKL 完全一样；
- 注册表 `InputMethodOverride` 只在系统设置里改默认输入法时才更新，日常切换不跟手；
- TSF 的 `GetActiveProfile()` 只反映调用线程自己的状态，后台进程拿到的是进程启动那一刻的值；
- 输入法自己的辅助窗口大多不可见（微信输入法、微软拼音根本不建窗口，豆包的窗口 `IsWindowVisible` 恒为 false）。

早期版本为此写过近千行探测代码（TSF、注册表、窗口指纹、手动指定、按语言猜），实测仍无法稳定区分，于是整层砍掉，只保留唯一被验证可靠的检测链路。

> **建议只安装一个中文输入法。** 装了两个时提示条依然正确（它只回答"中文还是英文"），只是不会再告诉你是哪一个。这在绝大多数场景下够用。

## 快速开始

**需要** Windows 8 及以上，Python 3.8+（要带 tcl/tk，python.org 的官方安装包默认带）。

1. 下载本目录全部文件，放到任意位置（建议固定一个目录，别放临时文件夹）。
2. 双击 `StartIMEIndicator.bat`，托盘出现一个蓝色「中」图标。
3. 切换中英文试试，提示条会从屏幕底部弹出来。

| 文件 | 用途 |
|---|---|
| `StartIMEIndicator.bat` | 正常启动（无控制台窗口） |
| `StartWithLog.bat` | 启动并记录 `events.log`，排查问题用 |
| `DemoHighlight.bat` | 演示各种状态的显示效果 |
| `_find_python.bat` | 被上面三个脚本调用，自动寻找可用的 Python |

脚本会自动探测可用的 Python（`pythonw` / `python` / `py` 启动器 / 官方安装目录），找不到会给出提示。也可以直接用命令行运行，见下节。

首次使用建议右键托盘图标 → **设置...**，把停留时长和透明度调到顺手。退出：右键托盘图标 → **退出**。

> **想开机自启？** 托盘右键 → 勾选「开机自启」即可（只在你当前用户下写一条 `HKCU\...\Run`，不需要管理员权限）。

## 命令行

```bat
python ime_indicator.py              :: 正常启动（托盘常驻）
python ime_indicator.py --once       :: 读一次当前状态并打印，然后退出
python ime_indicator.py --debug      :: 每 200ms 打印一次采样，Ctrl+C 结束
python ime_indicator.py --debug 30   :: 同上，30 秒后自动结束
python ime_indicator.py --demo       :: 只弹演示动画，不常驻
python ime_indicator.py --log        :: 启动时开启 events.log
python ime_indicator.py --version
```

`--once` 是排查"为什么没反应"最快的手段：

```
前台窗口: 0x208AC  Chrome_WidgetWin_1
输入语言: 0x0804  中文
中文: 是   全角: 否   可靠: True
大写锁定: 关
```

如果它打印 `中文: 是`，说明检测链路正常，问题在别处（例如前台是全屏游戏，被全屏策略静音了）。

## 配置

配置文件是程序目录下的 `config.json`，用设置界面改最省事（右键托盘 → 设置）。手工编辑也可以，改完重启生效。示例见 [`config.example.json`](config.example.json)。

| 键 | 默认 | 说明 |
|---|---|---|
| `duration` | `1.6` | 提示条停留秒数 |
| `always_on` | `false` | 常驻显示，不自动隐藏 |
| `margin_bottom` | `38` | 距屏幕工作区底部像素 |
| `opacity` | `0.85` | 整体不透明度 |
| `transparent_bg` | `false` | 去掉面板底色，只留文字 |
| `follow_mouse_monitor` | `true` | 显示在鼠标所在的显示器上 |
| `show_on_startup` | `true` | 启动时先提示一次 |
| `show_on_mode_change` | `true` | 中英文切换时提示 |
| `show_on_fullwidth_change` | `true` | 全角/半角切换时提示 |
| `show_on_caps_change` | `false` | 大写锁定时提示 |
| `show_on_window_change` | `false` | 切换窗口时提示（开了就是每切到一个新窗口都弹一次） |
| `show_fullwidth` | `true` | 是否显示「全角 / 半角」 |
| `poll_ms` | `60` | 检测间隔，20 / 40 / 60 / 100 / 200 |
| `hook_hotkeys` | `true` | 监听切换键，命中后立刻加速轮询 |
| `fullscreen_policy` | `"pause"` | 全屏时：`pause` 静默 / `reduce` 降频 / `normal` 正常 |

`show_on_window_change` 默认关闭的原因：从中文的记事本切到英文的浏览器时状态确实变了，但这不是用户主动切换，每次都弹会很烦。默认只在**同一个窗口内**变化才提示。

打开它之后的行为是「**每切到一个新窗口就弹一次**」——哪怕新窗口的状态跟刚才完全一样。这样才有"我切过去了，看一眼"的意义；只在不同时才弹的话，切两个状态相同的窗口什么都不会发生，看起来就像功能没生效。

## 工作原理

检测只有一条链路，全部走 IMM32：

```
GetForegroundWindow()                    前台窗口
  ├─ GetKeyboardLayout(窗口线程) & 0xFFFF  输入语言：0804=中文 0409=英语
  └─ GetGUIThreadInfo(tid).hwndFocus     真正有焦点的控件（不是顶层窗口）
       └─ ImmGetContext / ImmGetOpenStatus
       └─ ImmGetConversionStatus         conv & 0x1 = 中文，conv & 0x8 = 全角
   回退：ImmGetDefaultIMEWnd + SendMessageTimeoutW(WM_IME_CONTROL,
         IMC_GETCONVERSIONMODE, SMTO_ABORTIFHUNG, 10ms)
```

**语言和状态是两条独立的线**：语言来自 HKL（切中文/英语键盘时变），状态来自 IMM（中文输入法内按 Shift 时变，HKL 不动）。两者交叉才得出上表那三种情况。

几个踩过的坑，留作参考：

- **必须查焦点控件**。只查顶层窗口，很多程序返回线程默认值（恒英文）。
- **轮询而不是等通知**。`WM_INPUTLANGCHANGE` 只投递给有焦点的窗口，后台隐藏窗口永远收不到（实测一整晚 0 次）。60ms 轮询最坏只慢 60ms。
- **回退路径必须带超时**。用 `SendMessageTimeout` 而不是 `SendMessage`：前台是全速渲染的游戏时，同步消息会堵住它的消息循环，表现为掉帧。
- **键盘钩子只提速，不检测**。`Alt+Shift` / `Ctrl+Shift` / `Win+Space` 命中时把轮询间隔临时降到 20ms。钩子回调里不做任何磁盘 I/O 和跨进程查询——Windows 会因回调超时静默卸载钩子。
- **噪声窗口过滤**。点任务栏、开始菜单、桌面时前台会瞬间变成壳窗口，它们的输入状态恒英文。这类窗口沿用上一次真正应用窗口的结果，否则提示条会自己乱弹。
- **全角为什么有时要靠推断**。标准做法是输入法切换全角时置位 `IME_CMODE_FULLSHAPE`，但个别纯 TSF 输入法实测不写这个位。按下 `Shift+Space` 时先按"翻转"显示，1.2 秒内若 IMM 给出相同结果就确认，否则以推断值为准；过期后回到真实读数且**不再弹窗**。这条推断**只对中文键盘生效**——英语键盘的 `Shift+Space` 就是一个普通空格。

## 隐私

这个工具会全局监听键盘，所以有必要说清楚它到底做了什么：

- **不联网**。代码里没有任何 socket / HTTP / 更新检查，断网照常工作。
- **不记录输入内容**。键盘钩子只读按键的虚拟键码（`vkCode`），用来判断"是不是 `Alt+Shift`、`Shift+Space` 这类组合键"，**不缓冲、不解析、不落盘任何字符**，也不关心你在哪个程序里输入。
- **不截屏、不读剪贴板、不访问网络位置**。
- **写注册表只有一处**：勾选「开机自启」时在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 写一条自己的路径，取消时删掉，不需要管理员权限。
- **本地文件只有两个**：`config.json`（你的设置）和手动开启日志时的 `events.log`，都在程序目录下，随时可删。

## 常见问题

**启动后托盘图标闪一下就没了？**
用 `StartWithLog.bat` 启动，然后看程序目录下的 `events.log`；如果出现 `crash.log`，里面是完整堆栈。最常见的原因是没有装带 tcl/tk 的 Python——命令行跑一次 `python -c "import tkinter"` 就能确认。

**切换输入法完全没反应？**
先跑 `python ime_indicator.py --once`：
- 打印 `中文: 是/否`（而不是 `?`）→ 检测正常，检查是不是在全屏游戏里（默认策略会静音）。
- 打印 `可靠: False` → 这个窗口不响应 IMM 查询，多半是 UWP 或特殊自绘程序。

**任务栏右下角那个图标能不能不要？**
可以，托盘右键 → 退出即可；不想让它自启就不勾「开机自启」。

**能不能显示"现在是搜狗还是微软拼音"？**
不能，原因见上文「为什么不显示输入法的名字」。这是 Windows 的限制，不是没做。

**支持 Windows 7 吗？**
不支持。用到了 Windows 8 才有的 `SHQueryUserNotificationState`。理论上可以降级兼容，但没做。

**支持多显示器吗？**
支持。默认显示在鼠标所在的那块屏幕上（`follow_mouse_monitor`）。

## 已知限制

- **独占全屏游戏下看不见**。分层窗口（layered window）会被 DWM 绕过，提示条画在游戏画面之外。默认策略是 `pause`——游戏里完全不弹，零干扰；想看到就把游戏改成无边框/窗口化，并把 `fullscreen_policy` 设为 `normal`。
- **不区分具体输入法**（见上文）。
- **UWP / 部分沙盒应用**读不到 IMM 状态，会显示「状态未知」。这类程序本身也不响应普通输入法切换。
- **只在 Windows 上可用**。检测依赖 IMM32 和 Win32 API，macOS / Linux 用不了。

## 卸载

1. 托盘右键 → 退出（先关掉正在运行的实例）。
2. 如果开过「开机自启」，重新启动一次并取消勾选，或者手动删掉注册表这一项：
   `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `IMEIndicator`。
3. 删掉整个程序目录即可，没有安装程序、没有服务、没有其他残留。
